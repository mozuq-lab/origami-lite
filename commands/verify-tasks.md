# verify-tasks

## 目的

`/origami:split-spec` で生成されたタスク一覧の完了状況を確認し、進捗レポートを表示します。各タスクのチェックボックス状態を集計し、完了率や未完了タスクの一覧を提供することで、テストドキュメント生成の進捗を可視化します。

**機能別ディレクトリ方式対応**: 各タスクの完了状況は、対応する機能ディレクトリ（`F-XXX_{機能名}/`）内の4つの出力ファイルの存在も確認します。

**引数で仕様書ディレクトリを指定**することで、特定の仕様書の進捗のみを確認できます。

## 事前準備

1. **追加ルールの読み込み**
   - `docs/rule` ディレクトリが存在する場合は読み込み
   - `docs/rule/origami` ディレクトリが存在する場合は読み込み
   - 各ディレクトリ内のすべてのファイルを読み込み、追加ルールとして適用

2. **ディレクトリパスの解決** 🔵
   - 引数で指定されたパスからディレクトリを特定
   - フルパス指定時（`docs/origami/xxx/`）はそのまま使用
   - 仕様書名のみ指定時（`xxx`）は `docs/origami/{spec-name}/` に展開
   - パス末尾の `/` は自動補完

3. **タスクファイルの確認** 🔵
   - `{出力先}/tasks/task-list.md` が存在することを確認
   - 存在しない場合はエラーメッセージを表示し、`/origami:split-spec` の実行を案内

## 入力

| 引数 | 説明 | 必須 | 例 |
|------|------|------|-----|
| ディレクトリ | 仕様書ディレクトリパスまたは仕様書名 | ○ | `docs/origami/ecommerce-spec/` または `ecommerce-spec` |

### 使用例

```bash
# フルパス指定
/origami:verify-tasks docs/origami/ecommerce-spec/

# 仕様書名のみ指定（自動展開）
/origami:verify-tasks ecommerce-spec
```

### ディレクトリ解決ルール 🔵

| 入力形式 | 解決後のパス |
|---------|-------------|
| `ecommerce-spec` | `docs/origami/ecommerce-spec/` |
| `docs/origami/ecommerce-spec` | `docs/origami/ecommerce-spec/` |
| `docs/origami/ecommerce-spec/` | `docs/origami/ecommerce-spec/` |

## 実行内容

### 1. 引数解析とディレクトリ解決 🔵

- 引数で指定されたパスを解析
- 仕様書名のみの場合は `docs/origami/{spec-name}/` に展開
- パス末尾に `/` がない場合は追加
- 解決後のディレクトリパスを保持

**解決アルゴリズム**:
1. 引数が `docs/` で始まる場合 → フルパスとして扱う
2. 引数が `docs/` で始まらない場合 → `docs/origami/{引数}/` に展開
3. パス末尾の `/` を統一

### 2. タスク一覧読み込み 🔵

- `{解決後のディレクトリ}/tasks/task-list.md` を読み込み
- ファイルが存在しない場合はエラーを表示して処理中断
- タスク情報を解析

### 3. 機能ディレクトリ構造の確認 🔵

各タスクについて、対応する機能ディレクトリと出力ファイルの存在を確認：

```text
docs/origami/{仕様書名}/
├── F-001_ログイン/
│   ├── 01_機能詳細.md      ← 存在確認
│   ├── 02_動作仕様.md      ← 存在確認
│   ├── 03_境界値分析.md    ← 存在確認
│   └── 04_テストケース.md  ← 存在確認
├── F-002_ユーザー登録/
│   └── ...
└── tasks/
    └── task-list.md
```

**確認対象ファイル**:

| ファイル | 確認内容 |
|----------|----------|
| `{出力先}/F-XXX_{機能名}/01_機能詳細.md` | 存在チェック |
| `{出力先}/F-XXX_{機能名}/02_動作仕様.md` | 存在チェック |
| `{出力先}/F-XXX_{機能名}/03_境界値分析.md` | 存在チェック |
| `{出力先}/F-XXX_{機能名}/04_テストケース.md` | 存在チェック |

### 4. 完了状態集計 🔵

- 各タスクのチェックボックス（`- [x]` / `- [ ]`）の状態を確認
- 各機能ディレクトリ内の4ファイルの存在状態を確認（ファイル数をカウント）
- 完了タスク数と未完了タスク数をカウント
- 各タスクの機能ディレクトリ、ファイル数、状態を記録

### 5. 進捗計算 🔵

#### 5.1 フェーズ単位の進捗計算（v3.1.0〜）

**計算方法の変更**: タスク単位からフェーズ単位の進捗計算に変更

```
全体進捗 = 完了フェーズ数 / (タスク数 × 4)
```

**計算例**:
- タスク数: 2
- TASK-001: Phase 1-4 完了（4フェーズ）
- TASK-002: Phase 1 完了（1フェーズ）
- 全体進捗: 5 / (2 × 4) = 5/8 = 62.5%

#### 5.2 フェーズ別ステータスの集計

各タスクのフェーズ進捗テーブルから以下を集計：

| ステータス | 記号 | 意味 | カウント対象 |
|-----------|------|------|-------------|
| 未着手 | ⏳ | 未開始 | 未完了 |
| 実行中 | 🔄 | 現在実行中 | 未完了 |
| 完了 | ✅ | フェーズ完了 | 完了 |
| 要確認 | ⚠️ | 🔴項目あり | 未完了 |

#### 5.3 進捗バー生成

- 進捗バーを生成（視覚的な進捗表示）
- 残り作業量（残フェーズ数）を推定

### 6. レポート生成 🔵

進捗状況をフェーズ単位のサマリー形式で表示：
- 対象ディレクトリ
- 総タスク数・総フェーズ数
- 完了タスク数・完了フェーズ数
- 実行中タスク数・未着手タスク数
- 完了率（%）- フェーズ単位で計算
- フェーズ別進捗テーブル
- 次のアクション提案

## 出力ファイル確認 🔵

進捗レポート表示時に、各機能ディレクトリ内の出力ファイルの存在を確認します：

### 確認対象

各タスクについて、task-list.md から取得した「出力先」フィールドに基づいて以下のファイルを確認：

| ファイル | 確認内容 |
|----------|----------|
| `{出力先}/F-XXX_{機能名}/01_機能詳細.md` | 存在チェック |
| `{出力先}/F-XXX_{機能名}/02_動作仕様.md` | 存在チェック |
| `{出力先}/F-XXX_{機能名}/03_境界値分析.md` | 存在チェック |
| `{出力先}/F-XXX_{機能名}/04_テストケース.md` | 存在チェック |
| `{出力先}/F-XXX_{機能名}/05_観点レビュー.md` | 存在チェック（オプション） |

### ファイル数によるタスク状態判定

| ファイル数 | タスク状態 | 表示 |
|-----------|----------|------|
| 4/4（必須分） | 完了 | ✅ 完了 |
| 1〜3/4 | 作業中 | 🔲 作業中 |
| 0/4 | 未開始 | 🔲 未開始 |

**注**: Phase 5（`05_観点レビュー.md`）はオプションのため、4ファイル存在で「完了」と判定します。Phase 5 実行済みの場合は5ファイルが存在します。

### task-list.md から機能情報を取得 🔵

各タスクセクションから以下の情報を取得（**v3.1.0 新フォーマット対応**）：

```markdown
## TASK-001: F-001 ユーザー登録

**出力先**: docs/origami/{仕様書名}/F-001_ユーザー登録/

| 項目 | 内容 |
|------|------|
| タスクID | TASK-001 |
| 機能ID | F-001 |           ← この値を取得
| 機能名 | ユーザー登録 |      ← この値を取得
| 依存タスク | なし |

### フェーズ進捗

| Phase | Status | Output |
|-------|--------|--------|
| 1 | ✅ | 01_機能詳細.md |      ← この行を解析
| 2 | 🔄 | - |                    ← この行を解析
| 3 | ⏳ | - |                    ← この行を解析
| 4 | ⏳ | - |                    ← この行を解析
| 5 (任意) | — | - |              ← この行を解析（存在する場合）
```

### 解析ロジック 🔵

1. 各タスクセクション（`## TASK-XXX`）を検索
2. フェーズ進捗テーブル（`### フェーズ進捗`）を解析
3. 各フェーズの Status 列を取得
4. ステータス記号を集計:
   - ⏳ → 未着手カウント
   - 🔄 → 実行中カウント
   - ✅ → 完了カウント
   - ⚠️ → 要確認カウント
5. タスク全体のステータスを判定:
   - 全フェーズ ✅ → 完了
   - いずれかのフェーズが 🔄 → 実行中
   - 全フェーズ ⏳ → 未着手
   - いずれかのフェーズが ⚠️ → 要確認

## 実行後の確認

- 進捗レポートが表示されたことを確認
- 未完了タスクがある場合は次に実行すべきタスクを案内
- 全タスク完了の場合は生成されたドキュメントの一覧を表示
- 🔴項目がある場合は警告を表示

## 機能別ディレクトリ方式について 🔵

本コマンドは **機能別ディレクトリ方式** に対応しています。各機能が独立したディレクトリに出力されるため、コンテキストの肥大化を防ぎます。

### ディレクトリ構造

```text
docs/origami/{仕様書名}/
├── F-001_ログイン/              # 機能ディレクトリ
│   ├── 01_機能詳細.md           # Phase 1 出力
│   ├── 02_動作仕様.md           # Phase 1.5 出力
│   ├── 03_境界値分析.md         # Phase 2 出力
│   └── 04_テストケース.md       # Phase 3 出力
├── F-002_ユーザー登録/
│   └── ...
└── tasks/
    └── task-list.md             # タスク一覧（機能ID・機能名・出力先を含む）
```

### ディレクトリ命名規則

- **形式**: `F-{連番}_{機能論理名}/`
- **連番**: 3桁ゼロ埋め（001, 002, 003, ...）
- **機能論理名**: 日本語可、スペースはアンダースコアに置換
- **例**: `F-001_ログイン/`, `F-002_ユーザー_登録/`

### 注意事項

- 部分的に完了したタスク（一部ファイルのみ存在）は「作業中」として扱われます
- 機能ディレクトリの存在確認と4ファイルの存在確認を両方行います
- 既存の追記方式との互換性は維持しません（v3.0.0 Breaking Change）

## v3.1.0 Breaking Change

- **進捗計算方法の変更**: タスク単位 → フェーズ単位（完了フェーズ数 / 総フェーズ数）
- **出力形式の変更**: フェーズ別進捗テーブルの追加
- **task-list.md 解析**: 新フォーマット（フェーズ進捗テーブル付き）に対応
