# analyze-boundaries

## 目的

各機能の入力パラメータについて境界値を特定し、境界値テストのための分析表を作成します。
信号機システム（🟢🟡🔴）により、各境界値の確信度を可視化し、レビュー優先度を明確にします。

**実行コンテキストに応じたファイル出力**:
- **単独実行時**: 複数機能を一覧形式で `03_境界値分析表.md` に出力（後方互換）
- **タスク分割経由時**（`--target` 指定）: 単一機能の分析を `03_境界値分析.md` に出力

## 事前準備

1. **出力先ディレクトリの決定** 🔵
   - `--output` 引数が指定されている場合はそのディレクトリを使用
   - 指定がない場合は入力ファイル名から出力先を自動決定:
     - 入力ファイル名から拡張子を除去してディレクトリ名を生成
     - 出力先: `docs/origami/{仕様書名}/`
     - 例: `ecommerce-spec.md` → `docs/origami/ecommerce-spec/`

2. **前工程出力の確認**
   - `{出力先}/01_機能一覧.md` が存在する場合は読み込み
   - `{出力先}/02_動作仕様一覧.md` が存在する場合は読み込み
   - 存在しない場合は、入力として指定された仕様書から直接処理

3. **追加ルールの読み込み**
   - `docs/rule` ディレクトリが存在する場合は読み込み
   - `docs/rule/origami` ディレクトリが存在する場合は読み込み
   - 各ディレクトリ内のすべてのファイルを読み込み、追加ルールとして適用

4. **出力ディレクトリの作成**
   - 出力ディレクトリが存在しない場合は作成

## 入力

### 引数 🔵

| 引数 | 説明 | 必須 | 例 |
|------|------|------|-----|
| 仕様書 | 入力ファイルまたはURL | △ | `docs/requirements.md` |
| --output | 出力先ディレクトリ（機能ディレクトリを含む） | △ | `--output docs/origami/my-spec/F-001_ログイン/` |
| --target | 対象機能ID（タスク分割経由時） | △ | `--target F-001` |

**引数の組み合わせによる動作**:

| --target | --output | 出力ファイル名 | 用途 |
|----------|----------|---------------|------|
| なし | なし | `03_境界値分析表.md` | 単独実行（全機能分析） |
| なし | あり | `03_境界値分析表.md` | 単独実行（出力先指定） |
| あり | あり | `03_境界値分析.md` | タスク分割経由（単一機能） |

### 入力優先度（単独実行時）

| 優先度 | 入力 | 説明 |
|--------|------|------|
| 1 | {出力先}/01_機能一覧.md | 前工程の出力（推奨） |
| 2 | {出力先}/02_動作仕様一覧.md | Must/Never項目からパラメータを特定 |
| 3 | 仕様書（.md/.txt） | 単独実行時の直接入力 |
| 4 | URL | Web上のページ |

### タスク分割経由時の入力制限 🔵

`--target` オプション指定時は、以下のルールに従います：

- **入力**: `{出力先ディレクトリ}/02_動作仕様.md` のみ
- **重要**: 他の機能フォルダ（F-001_xxx/, F-002_xxx/ 等）のファイルは参照しない
- これにより、コンテキストサイズが一定に保たれます

### 使用例 🔵

```bash
# 単独実行（出力先自動決定）
/origami:analyze-boundaries docs/ecommerce-spec.md
# → docs/origami/ecommerce-spec/03_境界値分析表.md に出力

# 出力先を明示的に指定
/origami:analyze-boundaries --output docs/origami/my-project/
# → docs/origami/my-project/ の前工程出力を読み込み、03_境界値分析表.md に出力

# タスク分割経由（run-taskから呼び出し）
/origami:analyze-boundaries --output docs/origami/ecommerce-spec/F-001_ログイン/ --target F-001
# → docs/origami/ecommerce-spec/F-001_ログイン/03_境界値分析.md に出力
# ※ 入力は同ディレクトリの 02_動作仕様.md のみ
```

## 実行内容

1. **入力の読み込み**
   - 機能一覧または仕様書を読み込み
   - 機能ごとに入力パラメータを特定

2. **パラメータの特定**
   以下の情報を各パラメータについて整理する：
   - パラメータ名（変数名）
   - データ型（数値、文字列、日付、配列、列挙型等）
   - 制約（必須/任意、形式、範囲等）

3. **境界値の算出**
   データ型に応じて以下の境界値を算出する：

   **数値型**:
   - min: 最小値
   - min-1: 最小値未満（エラーケース）
   - min+1: 最小値直上
   - max: 最大値
   - max-1: 最大値直下
   - max+1: 最大値超過（エラーケース）

   **文字列型**:
   - minLength-1: 最小文字数未満（エラーケース）
   - minLength: 最小文字数
   - maxLength: 最大文字数
   - maxLength+1: 最大文字数超過（エラーケース）
   - 空文字列: ""
   - null/未定義

   **日付型**:
   - 開始日-1: 有効期間開始前（エラーケース）
   - 開始日: 有効期間開始日
   - 終了日: 有効期間終了日
   - 終了日+1: 有効期間終了後（エラーケース）

   **配列型**:
   - 0件: 空配列
   - 1件: 最小要素数
   - max件: 最大要素数
   - max+1件: 最大要素数超過（エラーケース）

   **列挙型**:
   - 各有効値
   - 無効値（存在しない値）

4. **不明境界値の処理**
   - 仕様書に明記されていない境界値は🔴マークで推測
   - 推奨値と確認アクションを記載
   - 一般的なWebアプリケーションの慣例に基づく推測は🟡マーク

5. **境界値テストケースの生成**
   - 各境界値に対応するテストケースを生成
   - 期待結果（正常/エラー）を明記

6. **信号機判定**
   - 各境界値に信号（🟢🟡🔴）を付与
   - 🔴項目は確認事項を詳細に記録

7. **サマリー生成**
   - 機能別・信号別の件数を集計

8. **出力ファイル名の決定** 🔵

   実行コンテキストに応じて出力ファイル名を切り替え：

   ```text
   IF --target オプションが指定されている THEN
     出力ファイル名 = "03_境界値分析.md"
   ELSE
     出力ファイル名 = "03_境界値分析表.md"
   END IF
   ```

   | 条件 | 出力ファイル名 | 出力形式 |
   |------|---------------|---------|
   | 単独実行（--targetなし） | `03_境界値分析表.md` | 複数機能を一覧形式で記載 |
   | タスク分割経由（--targetあり） | `03_境界値分析.md` | 単一機能の分析を記載 |

## 信号機判定基準

| 信号 | 判定条件 | 例 |
|------|---------|-----|
| 🟢 青信号 | 仕様書に境界値が明示されている | 「パスワードは8文字以上32文字以下」 |
| 🟢 青信号 | データ型から自明な境界値 | 整数型の最小値0 |
| 🟡 黄信号 | 一般的なWebアプリの慣例に基づく | メールアドレス最大254文字 |
| 🟡 黄信号 | フレームワーク・DBの制約に基づく | VARCHAR(255)の最大長 |
| 🔴 赤信号 | 仕様書に記載がなく推測 | 名前の最大文字数 |
| 🔴 赤信号 | 業務ドメイン固有の制約 | 注文数量の上限 |

## 境界値分析の参考技法

### 同値分割法との組み合わせ

境界値分析は同値分割法と組み合わせて使用すると効果的です：

1. **有効同値クラス**: 正常な入力値の範囲
   - 境界値: min, max
   - 代表値: (min + max) / 2

2. **無効同値クラス**: エラーとなる入力値の範囲
   - 境界値: min-1, max+1
   - 代表値: 明らかに無効な値

### 特殊値のテスト

境界値に加えて、以下の特殊値も考慮します：

- **null/undefined**: 値が未定義の場合
- **空文字列/空配列**: 長さ0の場合
- **特殊文字**: 制御文字、Unicode文字
- **SQLインジェクション文字列**: ' OR '1'='1
- **XSS文字列**: <script>alert(1)</script>
